## Commands

- Dev: `npm run dev` (http://localhost:3000)
- Build (SSG): `npm run build` — also validates content frontmatter against zod, so schema errors fail here
- Lint: `npm run lint` (eslint-config-next, includes react-hooks rules — they catch real bugs)
- Typecheck: `npx tsc --noEmit`
- **No test suite exists.** Verify changes with `lint` + `tsc` + `build`.

Gotchas:
- `tsconfig.json` does not set `noUnusedLocals`, so `npx tsc --noEmit` misses unused imports/vars. Run `npx tsc --noUnusedLocals --noUnusedParameters --noEmit` to catch dead code.
- Content scrapers are one-off dev tools that hit the live site (raw HTML cached in `scripts/scrape/.cache/`):
  `npx tsx scripts/scrape/episodes.ts` → `src/content/episodes/*.mdx` + `public/images/episodes`
  `npx tsx scripts/scrape/blog.ts` → `src/content/blog/*.mdx` + `public/images/blog`
- `npx tsx scripts/generate-brand-icons.ts` is one-off too: derives every square brand raster (app + manifest icons, `oba-logo-square.png` for JSON-LD, `podcast-artwork.png` for the feed) from `public/images/oba-logo.webp`. The logo is a 3.59:1 lockup, so squares use the **eye glyph alone**; only `oba-logo-square.png` keeps the full lockup. Ground is the white mark on the hero gradient (`heroGradientSvg()` reproduces `--gradient-hero`), matching the OG cards; `oba-logo-square.png` alone stays colour-on-white, since Google renders `Organization.logo` on light cards. It locates the glyph by alpha gutter at runtime and throws if it moves. sharp can't encode ICO, so pack the favicon separately: `magick public/images/.icon-src/{16,32,48}.png src/app/favicon.ico`. **The favicon is the one icon not cropped from the logo:** the glyph is four concentric bands at a ~50px stroke on a 778px glyph, so at 16-48px they fill in (`brand-guidelines.md` ch.8: "minimum on screen 1250 px wide"). `MARK` in the script is a small-size redraw whose every figure was measured off `oba-logo-white.png` — it drops the inner ring, opens the remaining stroke 50→72 and grows the iris 114→176, inventing no curve. The pupil is dropped at 16px only (the notch reads as a "C" there). Everything larger keeps the full glyph; don't unify them without treating it as a brand change. `scripts/assets/oba-eye-mark.svg` is written from the same constants — the mark's first vector original, a build input, deliberately not served. The favicon tile is the only icon with rounded corners (`MARK_RADIUS` = 1/8, whole pixels at 16/32/48) and so the only one keeping alpha — the corners sit on browser chrome of unknown colour. Everything else stays square and opaque: iOS masks `apple-icon.png` itself, Android crops the maskable icon, and the podcast/JSON-LD artwork is read flat.

## Architecture

- Next.js App Router + TypeScript + Tailwind CSS v4, **fully static (SSG)**. No database, no API routes, no account system.
- **Content is local files** in `src/content/` (episodes/*.mdx, blog/*.mdx, hosts.json, events.json, free-resources.json). Frontmatter is zod-validated (`src/lib/schemas.ts`); loaders in `src/lib/content/` are memoized. Add/edit content there — invalid frontmatter fails the build. `image` fields are optional; `eventImage()` / `resourceImage()` in `src/lib/utils.ts` supply the placeholders.
- **Site-wide config lives in `src/lib/site.ts`**: `siteConfig` (metadata, GA4 id, socials, `primaryCta` Contribute → `/speak`, `strategyMeetingUrl`), `aiSummary` (the footer "Get an AI summary" prompt), `primaryNav`, `footerNav`. Change nav/CTA there, not in components. Header: Resources · Podcast · Marketing · Ask AI · Participate · About · Contact.
- Component layers (`src/components/`): `ui/` design-system primitives → `layout/` (header/footer/nav) → `marketing/` (hero, CTASection, PageHero, DarkHero) → `content/` (cards, EventCard, FeaturedEventCard, LibsynPlayer, Markdown) → `forms/`. `home/` holds homepage sections (split out of `src/app/page.tsx`).
- **Only WebGL surface:** `home/HeroGlobe.tsx` — a `three` globe shown whole in the gap right of the hero copy (`GLOBE_BOX`), mounted via `home/HeroGlobeMount.tsx` (`next/dynamic`, `ssr: false`). `xl`-and-up only (below that the copy leaves no room), rAF paused offscreen, frozen under `prefers-reduced-motion`. Flights use framer-motion `animate()` — don't add GSAP or OrbitControls.
- Globe layers: 2,800 white points blanketing the whole sphere (the committed `home/landmask.ts` sets a per-point `aLand` flag that lifts opacity and size rather than filtering points; ocean stays a faint grid at `OCEAN_ALPHA`), and 14 bezier arcs anchored to land. The only ring layer left is the five people pins, pulsing in the same white as the dot shell (`PIN_COLOR`) — the globe is monochrome, no saturated color.
- No buttons on the globe: five people in `PEOPLE` are pinned at real coordinates, and the front-most pin inside the visible slice shows a circular portrait positioned from the render loop. Avatar needs `max-w-none` (the global `img { max-width: 100% }` clamps it to 0 against the zero-width anchor), and the active-index tracker must stay local to the effect — as a ref it survives effect re-runs while the DOM resets, so nothing ever shows. Names live in an `sr-only` list. Deliberately a **hollow shell** — no body, `depthTest: false` throughout; each layer fades as it turns away (`vFacing`) and that fade is the only depth cue, so don't drop it without adding an occluder. Arcs are `TubeGeometry` (`gl.lineWidth` is clamped to 1px) and use `NormalBlending` (additive saturates against `--gradient-hero-glow`). Regenerate the mask with `npx tsx scripts/generate-landmask.ts`.
- Design tokens live in `src/app/globals.css` under `@theme`. Use `cn()` (`src/lib/utils.ts`) for class merging — it's configured so the custom `text-*` type utilities don't collide with `text-<color>` utilities.
- **SEO/metadata:** page `metadata` goes through `pageMetadata()` (`src/lib/og/metadata.ts`); structured data via `src/lib/jsonld.ts`; OG images are built by `opengraph-image.tsx` routes (root, blog post, episode, event) on top of `src/lib/og/` — a page needs `image: "route"` in `pageMetadata()` to use its segment's card instead of the brand one. `/styleguide` uses `noindex: true`; `not-found.tsx` hand-rolls metadata because `pageMetadata` always sets a canonical and a 404 must have none. Icons/`manifest.ts`/`theme-color` come from `scripts/generate-brand-icons.ts`. RSS is `src/app/feed.xml`; `sitemap.ts`/`robots.ts` in `src/app/`. Legacy WordPress URLs and live-site aliases 301-redirected in `next.config.ts` (`/analyze` and `/marketing` → `/msm`). Legal: `/privacy`, `/terms`.

## Conventions & constraints

- **Agent layer** (`src/lib/agent/`): `llms.txt`, `llms-full.txt`, `/okf/*`, `<path>/md` mirrors,
  and `/podcast/episodes/<slug>/transcript.md`. All generated from `src/content` via the `AgentItem`
  shape — a public contract, so **extend it, never reshape it**, and generate any new surface the
  same way. `pageMetadata()` must keep restating `alternates.types` (Next replaces `alternates`
  wholesale, which silently dropped the RSS link from every page). Transcript text and `okfBundle()`
  are memoized because both are rebuilt once per generated file.
- **Transcripts are authored by hand in the episode Google Sheet**, not generated (WhisperX was
  dropped). Paste into a `transcript` column, run `npm run publish:episodes`; timestamps optional,
  and it syncs onto already-published episodes. `transcriptStatus` defaults to `reviewed` — set
  `machine` for un-reviewed ASR, since these are words attributed to named physicians.
  See `docs/ai-seo.md` and `docs/seo-audit.md`.

- **Copy must follow `docs/messaging-strategy.md`.** OBA is positioned as a professional platform for experienced ophthalmology leaders, not a lead-gen funnel; speaker/partner conversions are the primary CTAs. The marketing-analysis offer is at `/msm` (nav label "Marketing") and must stay labeled as an Ekwa service. Only verifiable claims are allowed (75+ episodes, six named hosts, since 2022, 100% ophthalmology) — never add "thousands of practices" or "weekly content" claims, and describe empty sections honestly. Read that doc before writing or changing any site copy.
- **Shadows are elevation-only** (floating/overlay surfaces: scrolled nav, dialogs, dropdowns). Cards use hairline borders — no decorative card shadows, no raw hex outside `@theme`.
- Forms (contact, newsletter, speaker, partnership, marketing analysis, panel registration) are **styled UI shells**: they validate client-side (vanilla React state) and show pending/success states, but submission is stubbed with `// TODO`. `ContactForm` variants: `contact` | `analyze` | `speaker` | `partnership`. Don't wire backends unless asked.
- There is **no auth**. Do not re-add `/login`, `/register`, or `/forgot-password`. Membership is account-free; newsletter is the soft CTA.
- Events have a Fall 2026 series in `src/content/events.json` and keeps an empty-state fallback. Only the Sept 17 panel carries the full landing-page layer; the rest are title + date and render as a short page. Don't fill them with invented copy.
- **`/resources/events/[slug]` is a content-driven landing-page template.** Each section is switched on by its own optional `eventSchema` field (`startDateTime`, `startTime`, `format`, `lede`, `aboutTitle`, `about[]`, `topics[]`, `audience[]`, `panelists[]`, `registrationNote`) and renders nothing when empty, so one route covers a bare title+date entry and a full registration page. Adding a panel is editing JSON, never code. `registrationUrl` is always an outbound link — this page never posts a form; signups live on the registration host. `FeaturedEventCard` links to the panel page, not straight to `registrationUrl`. Past events (vs. the module-level `BUILT_AT_MS`, since renders must stay pure) drop the register CTAs.
- `EventCountdown` is the site's only clock: a `useSyncExternalStore` subscription to one shared 1s interval, `getServerSnapshot` → 0 so SSR and first paint both show em-dash placeholders. Its tick is a value changing, not motion, so `prefers-reduced-motion` is intentionally not consulted; digits are `aria-hidden` behind one `sr-only` sentence.
- Both content sections use the homepage's language. Topics = `ProblemAreas`' band (hairlines in the grid, `[n]` mono counters, centred two-tone header), at 2 columns not 4 because the copy is ~40 words; cell padding is `odd:pl-0`/`even:pr-0` since it wraps to 2x2; the vertical rule is drawn per cell (`i % 2 === 0 && i + 1 < len`), not with `divide-x`, which on a wrapped grid hangs a hairline off the right edge at the end of row one. `EventPanelists` = `StatBento`'s light tile (`rounded-2xl`, hairline border, `accent-50→accent-100`) on a `bento-grid` (`bento-cell` needs that parent to clip its gap hairlines), with `SpeakerCard`'s square `rounded-xl` portrait; a slate version was tried and reverted. **The tile ground is why a grid works here** — bios vary 2x in length and bare text blocks in a grid read as ragged; don't strip the ground and keep the grid. Tiles disclose like `SpeakerCard`: header shows the person, bio expands. `headshotFor()` hits the filesystem, so it splits `EventPanelists` (server, resolves headshot paths) → `EventPanelistGrid` (`"use client"`, tiles + open state). Hand-rolled, not Radix — the bio must stay in the static HTML, so it's clipped by a `0fr` grid row and marked `inert`; `h3 > button` (a button takes phrasing content only); a panelist with no bio gets a plain header, not a dead button. Open state sits in the grid because a click opens the whole **row** — that needs the column count, so the grid classes and the `(min-width: 640px)` query must change together, and a breakpoint change closes what was open. Bio goes in an inset pane (`rounded-(--radius-md) border-line bg-canvas` — `EventCountdown`'s inset-cell treatment), stretched to the tile's bottom padding via `flex-auto` on the wrapper + `flex-1` on the pane so a height-matched row doesn't end in bare steel; `flex-auto` not `flex-1`, since a 0 basis collapses the tile to its header. Photos resolve by name via `headshotFor()` (exact match, frosted-monogram fallback) — drop `first-last.jpg` in `public/images/headshots/`. Keep the portrait modest: the headshots have unrelated backgrounds, so a bigger face means a louder background (`HostCard`'s reasoning). **Hero takes the reg page's parts in this site's materials**, claim first: eyebrow → h1 → `EventFactsStrip` (Date/Time/Format chips, frosted, an equal-column grid so all three hold one row — as a wrapped flex row they overran the copy column by 6px) → `EventCountdown` → lede → `EventHeroPanelists` (face + name + role, a 2-col grid — a flex row wrapped unevenly) → `EventRegisterCard` in the aside. Chips + clock ride `DarkHero`'s new `titleMeta` slot (row between h1 and lede), the line-up its `proof` slot; pass `null`, not an empty wrapper, or the slot's `mt-8` still lands (`hasEventFacts()` is exported for that). **No breadcrumbs here** — the trail cost ~200px at the top of a long copy column, and the page emits no `BreadcrumbList` JSON-LD, so the row went entirely. `DarkHero` gained `asideAlign` and `titleSize="h2"` (a wide form aside narrows the copy column; the display step set this title at four lines). `EventRegisterCard` fills the slot the reg page gives its form and carries the form (`forms/EventRegisterForm`): the same nine fields in order (first/last name, email, phone, job title, practice name, text-reminder + practice-owner selects, question), submit, security line, and the Moderated Q&A / Replay included / Practical playbooks tags. **Submission is stubbed** like every form here — the live page POSTs `{event_key, first_name, …, question, source_id}` as `no-cors` JSON to a Google Apps Script endpoint, recorded in the component; wiring it is that POST + an `eventKey`. **Invents nothing about seats or scarcity** (no ticker, no "limited seats", no emoji). The form is the ask, so the hero has no action row and a registerable panel ends after the panelists — no closing CTA band; a panel with nowhere to register keeps the standing contributor `CTASection`. The card is **white** (bento radius, `line` hairline, default light controls filled `canvas-subtle` so they read against the card, reg page's placeholders) — a form is worked in, not read, so it lifts off the gradient rather than competing with it, as the reg page does. Aside runs `asideWidth="wide"`; a past panel renders no card. All of it is conditional, so bare title+date events still get the short page.
- **Deleted pages — do not re-add:** webinar archive + replays (`/resources/webinars`, incl. the webinar schema/loaders), newsletter (`/resources/newsletter`), FAQs (`/faq`), podcast hub (`/podcast`), `/partnerships`, `/membership`, reviews (`/reviews` → `/about`, pulled for having no real reviews; `reviews.json`, `reviewSchema`, `getAllReviews()` and `ReviewWall` are kept unused so it can come back whole). All 301-redirected in `next.config.ts`. `/podcast/episodes` is the podcast landing page and carries the `PodcastSeries` JSON-LD. Newsletter sign-up is the footer band only (`#newsletter`); general FAQs are the homepage section only (`#faq`). Partner conversion runs through `/contact`, which holds the `partnership` ContactForm variant + `PARTNERSHIP_FAQS` in a `#partnership` section. `PODCAST_FAQS` and `membershipFaqs` are kept but unused. About is a plain nav link (its dropdown had only Reviews left).
- `LibsynPlayer` plays direct Libsyn MP3s — keep `preload="none"` and its buffering/error/no-audio states. It is the episode transport: the 64-bar waveform *is* the seek control (transparent native range input over the bars). Bar geometry mirrors `ui/Waveform.tsx`'s 3px bars on a 6px pitch about the centre line; 160 bars thinned 1-in-4 / 1-in-2 / all by breakpoint to hold that width. Bars are audio-reactive: colour = position, height = live audio from a real `AnalyserNode`, so motion never costs the seek control its meaning; paused they ease back to the silhouette. Heights are `scaleY` written in rAF (React owns colour and a constant transform it never rewrites). Needs `crossOrigin="anonymous"`; `onError` remounts a plain element so audio survives a CORS failure. Reduced motion drops reactivity in JS. The silhouette is seeded from the slug — a fingerprint, not amplitude data; never label it as audio analysis.
- Episode pages (`/podcast/episodes/[slug]`) are built as brand artwork per `brand-guidelines.md`: `EpisodeHero` on `PAGEBG` + `.dot-field`, hero lobe at 35%, h1 as a single white claim — no byline and no dimmed turn, because the portraits name everyone (don't split a title at render time to recreate one; add an authored `subtitle` instead). The hero's right column is `EpisodePortraits` (4:5 speaker tiles, radius 18, monogram fallback, always a single row capped at four, omitted when nobody is credited; the hero's aside width scales with the count so tiles divide a wider column instead of shrinking in a fixed one), not the episode artwork; each tile carries the person's name in Inter, since a name is content rather than a label. Guests resolve to a photo by name via `headshotFor()` out of `public/images/headshots/` (`first-last.jpg`); matching is exact on the slug and must stay exact — a near-miss puts the wrong face on a named person. A miss falls through to the monogram. No `EP n / total` counter (numbers run 1–124 across 75 episodes). No entrance animation — only the playhead and `animate-live-dot` move. One CTA: `<CTASection secondary={null} />`.
- Tailwind v4 token-var syntax uses parens, e.g. `pt-(--header-offset)` (the token pages use to clear the floating header).
- Dark-hero routes must be listed in `DARK_HERO_ROUTES` in `SiteHeader` so the floating nav uses light text.
